# SmartODL — Deep Audit (31 Oct 2026)

Scope: full backend (`backend/`), frontend (`frontend/src`), live MySQL schema (53 tables),
and a real browser crawl. Har finding ke saath **proof** hai — koi guess nahi.

Kuch bhi claim karne se pehle 3 tarah se check kiya:

1. **Static** — SQL injection, auth coverage, secrets, upload validation, dependency advisories.
2. **Live API** — curl se authorization matrix, IDOR, JWT forgery, rate limits, payloads.
3. **Real browser** (headless Chromium + actual login) — 72 routes crawl, JS errors, failed
   requests, a11y scan, duplicate-request measurement.

Reproduce karne ke liye scripts repo me hain: `tools/audit/crawl-routes.py`, `tools/audit/a11y-scan.py`, `tools/audit/schema-drift.py`.

## P1 — High

### 1. Signed-in user ke har hard reload par `GET /api/gamification/me` 401

**Kya hota hai:** jab user already logged-in hai aur page reload (F5) karta hai, navbar ka
XP/level widget bina token ke API call kar deta hai → 401 → widget khaali reh jaata hai
(data load hi nahi hota) aur console me error aata hai.

**Root cause:** access token **memory-only** hai (`services/api.js`), par profile
`cachedUser` (localStorage) se turant mil jaata hai. `AuthContext` ka `user` non-null hota hai
jabki `tokens.access()` khaali hai (session restore abhi chal raha hai). `MainLayout` ka
`useEffect(..., [user?.id])` usi kshan fire ho jaata hai.

**Evidence (browser crawl, role = student):**
```
/profile     → 401 GET /api/gamification/me
/settings    → 401 GET /api/gamification/me
/subscription→ 401 GET /api/gamification/me
/admin/landing-builder → 401 GET /api/gamification/me
```
Same token ke saath curl 200 deta hai — matlab bug frontend ki timing ka hai:
```
curl -H "Authorization: Bearer <token>" /api/gamification/me → 200 {level:1,...}
```

**Side-effect risk:** ye 401 axios interceptor ke `401 → silentRefresh` path me bhi jaata hai,
jo `AuthContext` ke apne refresh ke saath parallel chal sakta hai. Storm-guard hai isliye aaj
logout nahi ho raha, par ye ek bekaar race hai.

**Fix (chhota):** `useAuth()` se `loading` bhi lo aur `if (loading || !user) return;`
`layouts/MainLayout.jsx` aur `student/Dashboard.jsx` me. (Ya `api.js` me "restore in progress"
par request ko queue karo — bada fix.)

---

### 2. Admin page feature-gated API call karta hai → red 403 error

`achievements_enabled = 0` default hai (settings table check kiya). Student route
`/student/achievements` `FeatureGate` me wrapped hai (sahi), par **admin manager**
`/admin/achievements` nahi hai — wo seedha `GET /api/achievements` maarta hai:

```
GET /api/achievements (owner token) → 403 {"error":"Achievements is currently disabled by the administrator"}
```
Page khulta hai, turant upar red toast aata hai aur list khaali. Admin ko feature **manage**
karne se feature ka *student-facing* off hona nahi rokna chahiye.

**Fix:** `/admin/achievements` route ko `FeatureGate` me wrap karo (ya 403 par
"feature off — Settings se on karo" wala neutral banner dikhao), ya backend me admin role ko
`featureGate` se exempt karo (`if (req.user?.role === 'admin') return next()`).

## P2 — Medium

### 4. Login par brute-force limit bahut dheeli

```
AUTH_RATE_LIMIT_MAX default = 100 attempts / 15 min / IP
```
8 galat password par bhi koi 429 nahi aaya (test kiya). 100/15min = ~9,600/day/IP, aur
per-account lockout/backoff bilkul nahi hai. Campus NAT par ek lab pura budget kha sakti hai,
ya ek attacker ko ~10k password guesses milte hain.
**Fix:** login-only limiter 10–20/15min + per-email exponential backoff (5 fails → 1 min, etc.).

### 5. UPI admin page load hote hi 400 error dikhata hai

```
GET /api/admin/upi-payments/preview → 400 "First set a valid UPI ID in Website Settings…"
```
Jab tak UPI ID set nahi hai (aur `upi_enabled = 0` hai) tab tak page par red error aata hai.
Server ka message sahi hai, par 400 par error state nahi — "setup pending" empty state hona chahiye.

### 6. `database/education_platform.sql` schema se peeche hai (drift)

Dump parse karke live `information_schema` se compare kiya:

```
dump tables: 53   live tables: 53
certificate_templates: live has columns the dump lacks -> ['logo_path']
certificates        : live has columns the dump lacks -> ['design_snapshot', 'template_id']
```
Fresh install **break nahi** hota, kyunki boot par `certificateTemplates.ensureSchema()` ye
columns khud add karta hai — par `docs/DATABASE.md` ka "dump = current schema" claim galat
ho jaata hai. Har naye column ke liye dump regenerate karna chahiye.

### 7. `certificates` table par koi foreign key nahi

`certificates` (aur `achievements`, `categories`, `plans`, `site_pages`, `lesson_watch_buckets`,
`point_adjustments`, `landing_*`) me FK nahi hai. User delete karne par uske certificates
orphan reh jaate hain — public `/cert/<token>` link zinda rehta hai (deleted student ka naam
verify page par dikhta hai). Abhi live data me orphan 0 hai (check kiya), par invariant DB me
enforced nahi.
**Fix:** `FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE` (ya delete flow me
explicit cleanup + `revoked_at` stamp).

### 8. Sabse zyada risk wale controllers ka koi test nahi

25 unit test files hain, par wo services/utils cover karte hain (certificate, quiz, proctor,
watch, payment crypto…). **Zero tests** in par:
`auth.controller` (login/refresh/reset), `course.controller` (enroll, updateProgress, paid gate),
`user.controller` (permissions), `quiz.controller` (attempt submit/scoring), `certificate.controller` (issue).
Yahi 5 files hain jahan bug ka business impact sabse bada hai.

## Fixes in detail

**#1 — token restore race.** `layouts/MainLayout.jsx` aur `student/Dashboard.jsx` ab
`useAuth().loading` ka intezaar karte hain, phir API call karte hain. Isse wo 401 khatam jo har
hard reload par aata tha (aur axios ka `401 → silentRefresh` path bhi trigger karta tha).

**#2 — feature gate vs admin.** `routes/index.js` ka `featureGate()` ab
`{ allowStaff: true }` leta hai: gate band hone par bhi owner/admin/developer ko andar jaane deta
hai (token optional decode karke), student ko 403 hi milta hai. Achievements par lagaya.

**#4 — login backoff.** Naya `services/loginGuard.service.js`:
key = **email + IP** (sirf email = victim ko lock karna possible; sirf IP = poore lab ko lock).
8 fails / 15 min → 5 min pause, safal login par reset, expiring buckets (memory leak nahi).
IP limiter waisa hi (100/15min) hai kyunki campus NAT ke liye chhota ceiling galat hoga.
Message ke dono cases (email maujood / nahi) **bilkul same** hain — account enumeration nahi hoti.

**#5 — UPI setup state.** Backend ab 400 nahi, `200 {configured:false}` deta hai; frontend
`configured:false` par neutral panel dikhata hai (QR block render hi nahi hota).

**#6 / #7 — schema.** Dump me 3 missing columns add + certificates FKs. FK ko dump ke **end**
me `ALTER TABLE` se rakha (alphabetical order me `certificates` `users` se pehle banta hai, isliye
inline FK import order par depend karta).

**#8 — tests.** `dwellVerdict()` ab pure function hai (`services/lessonOpens.service.js`) — controller
usi ko call karta hai, aur 7 unit tests usi rule ko cover karte hain jo student ko 400 deta hai.
